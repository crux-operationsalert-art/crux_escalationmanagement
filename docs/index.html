Before it is useful

The software is finished. What it knows is not, yet. In this order:

  1. Set up mail. Mail → choose a provider, paste its key, send yourself a test. Until this is done the tool works and tells nobody.
  2. Empty the tool. Data setup → Empty the tool. It shows you exactly what would go before it goes, and asks you to type the words.
  3. Load the masters, in load order: Chairs, People, Geography, Clients and branches, Assignments, Rates.
  4. Load SLA rules. Without them every assignment takes the default of 1,440 business minutes and every deadline in the tool is a guess.
  5. Load the escalation matrix. Optional — escalation falls back to the reporting line and says so — but every fallback raises an alert.
  6. Confirm the festival dates for the year against the gazette. An unconfirmed holiday shows on the calendar and shortens no deadline until somebody fixes it.

Every file kind has a Download template button giving the exact headers, one example row, and the rule for every column.

How it is built

Postgres on Supabase in ap-south-1, with row-level security forced on every table. Three edge functions — the front door, the ported API, and the mail sender — so there is no server to keep alive. Scheduled work runs inside the database: auto-close, the SLA sweep, sub-TATs, escalation and strikes every fifteen minutes, and the outbox drains every minute when there is something in it.
